# 第一阶段总结与维护计划

日期：2026-11-03。最新软件 Release：[v0.3.1](https://github.com/Leonhart999/nav2lint/releases/tag/v0.3.1)。

## 阶段决策

第一阶段完成，nav2lint 从主动扩展功能转为维护模式。仓库保留且不归档。这是阶段性结题，不代表已经完整验证 Nav2 的所有配置，也不等于承诺 1.0 级别的稳定性。

`main` 上包含 v0.3.1 发布后补充的入门和阶段总结文档，原有版本标签没有移动。本次收尾不改变程序运行行为。

## 已交付范围

- 不安装 ROS 即可运行的 Nav2 YAML 静态检查工具，内置 Humble、Jazzy、Kilted、Rolling 的源码快照参数表与参考配置。
- YAML 结构、参数类型、插件注册、已知发行版迁移、跨参数一致性和疑似拼写错误检查。
- 带文件名和行号的诊断，文本、逐行和 JSON 输出，规则解释与参数依据查询。
- 修复预览、显式启用的机械修复、项目配置、级别调整和注释抑制。
- 目录扫描、watch、手动启动的 VS Code 任务和 pre-commit hook。它是带编辑器集成的命令行工具，不是 Marketplace 扩展。
- Windows/Linux 自动化测试、发行包构建、独立环境 wheel 安装验证、中英 README、入门指南、演示动图和公开版本 Release。

## 已知限制

- 参数表是所记录源码快照的不完整静态近似，不是运行时探测。T404 只说明表中未收录，不能证明 Nav2 会忽略该参数。
- 发行版名称不能保证与实际安装的 Nav2 包修订完全一致，尤其是 Rolling 和下游修改，需要结合实际版本核查依据。
- 不解析启动时参数覆盖、改写后的 YAML，也不检查行为树 XML。
- 不为第三方插件提供完整参数表或类型检查，插件导出名称由其 plugin XML 决定。
- 发行版推断和拼写建议是启发式判断。已知版本时应显式传入 `--distro`。
- 自动修复不能推断机器人特定的配置意图。先用 `--diff` 预览，备份后再使用 `--fix`。
- 检查通过不代表 TF、传感器、定位、运动安全、导航效果或 Nav2 启动都正常，仍须仿真和实际运行验证。

## 维护规则

继续接受：

1. 可复现的崩溃、错误诊断，尤其是不安全修复和影响较大的误报。
2. 有目标版本依据、附带回归测试的参数表和迁移规则纠错。
3. 文档、安装说明纠错，以及必要的打包和 CI 修复。

新增功能只有在明确使用需求足以支撑范围和维护成本时才评估。不承诺固定响应时间、发版周期，也不自动承诺支持未来 ROS 2/Nav2 版本。软件发版仍采用版本号、CHANGELOG、标签和 GitHub Release；纯文档维护可以更新 `main`，不改变软件版本号。

暂缓但未承诺：PyPI 发布、更丰富的旧参数迁移解释和额外编辑器/UI 集成。独立 GUI、Web 服务、Marketplace 扩展、完整参数表或继续扩大语料库，都不是本阶段结题条件。

## 如何反馈问题

通过 [GitHub Issue](https://github.com/Leonhart999/nav2lint/issues/new?template=bug_report.md) 提供：

- `nav2lint --version`、Python 版本、操作系统、目标 ROS 2/Nav2 版本；已知时附源码 commit。
- 原始命令、相关输出和能复现问题的最小 YAML。
- 预期行为；报告误报时附对应文档或源码依据。
- 修复问题附脱敏后的修改前后 diff，并说明 `--diff` 是否已展示该改动。

删除 token、凭据、私人路径、网络地址和保密机器人配置。复现 `--fix` 问题时使用临时副本，不操作部署中机器人的实际配置。

## 以后如何接着维护

入口为[五分钟上手](quickstart_zh.md)、[README](../README.zh-CN.md) 和 [CHANGELOG](../CHANGELOG.md)。开发时安装 `.[dev]`，执行 `python -m pytest -q`，其中包含打包测试。数据集和构建缓存放在仓库外。维护修复应补充有针对性的回归测试，正式发版前核实 CI。
